## Decisions

1. **Migration CM1 → CM2** — **Choix** : CM2 (DB) devient l'unique source
   opérationnelle, CM1 abandonné comme outil. **Rationale** : CM1 n'est plus à jour.
   **Alternative rejetée** : importer les données CM1 (rien à importer, il est périmé).
2. **Macros : ne rien réparer dans cette session** — **Choix** : documenter #65 et
   planifier une session dédiée. **Rationale** : le correctif touche ~19 fiches du Coach
   Nutrition + le moteur + un ADR — hors périmètre d'un « refaire le menu ».
   **Alternative rejetée** : correctif partiel (unités seules) — porterait la couverture
   à ~50 %, un total *crédible mais faux* sur l'autre moitié (piège « signal absent »).

## Problems

1. **Moteur de macros systématiquement non concluant** — **Symptôme** : 7-25 % de
   couverture sur TOUTES les recettes, existantes comprises ; presque chaque ingrédient
   « non résolu ». **Cause** : quatre, mesurées — (a) un état (`-cuite`/`-cru`) dans le
   NOM de ~19 fiches aliments pollue la clé d'appariement (+ doublons `blanc-poulet` /
   `blanc-poulet-cru`, `pasteque` / `pasteque-crue`) ; (b) `match_entry` asymétrique ne
   matche que si l'ingrédient ⊇ clé, donc « patate douce » ne trouve pas
   « patate douce cuite » ; (c) unités comptées/conteneurs (`pièce`, `boîte`, `brique`,
   `gousse`) non pesées, et `normalize_name` supprime le « (environ N g) » de la ligne ;
   (d) sel/poivre/épices comptés comme non résolus. **Solution** : documentée dans #65,
   session dédiée. **Prévention** : skill weekly-prep étape 11 interdit désormais
   d'afficher un total non concluant → lire `coverage`, dire « non concluant, X % ».
2. **git status vide sur mon edit de skill** — **Symptôme** : `git status`/`git diff`
   ne voyaient pas ma modification de weekly-prep alors que le contenu était bien sur
   disque. **Cause** : session concurrente (ou hook) qui a commité l'edit ; MarketPlace
   porte d'autres changements non miens (dev-cli-launchers, ref-wcm-secrets). **Solution** :
   vérifié `git show HEAD == worktree`, contenu correct, rien à committer côté MP.
   **Prévention** : sur un repo partagé par plusieurs sessions, vérifier `git show HEAD:<path>`
   avant de conclure à une perte d'edit.
