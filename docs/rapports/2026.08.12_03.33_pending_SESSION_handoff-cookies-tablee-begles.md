## Decisions

1. **Pas de passkey Google sur le VPS**
   - **Choix** : rester sur le reseed ciblé manuel pour les sessions vraiment mortes
   - **Rationale** : le credential serait exfiltrable en clair ; bénéfice
     (confort de self-heal) très inférieur au risque (compte Google entier)
   - **Alternative rejetée** : enrôlement `enroll_passkey_local.py` — scripts
     conservés dans le repo si la décision change
2. **Implication de plat ≠ ingrédient explicite** (fix carbonara)
   - **Choix** : le marqueur végétarien n'annule QUE les noms de plats
     (`MEAT_IMPLIED_DISHES`), jamais un ingrédient carné explicite
   - **Rationale** : doctrine « mieux vaut une alerte de trop » préservée sur
     les libellés mixtes (« burger végétarien au bacon » alerte toujours)
3. **Réamorcer la chaîne ai-export existante plutôt que la re-brancher à chaud**
   - **Choix** : sync + rclone push (mécanisme en place), unification vers le
     CHV tracée en issue (#47) plutôt qu'implémentée dans la foulée
   - **Rationale** : la chaîne marche pour chatgpt/perplexity ; le re-branchement
     touche `_load_cookies` + formats — travail cadré, pas un patch de fin de session

## Problems

   - **Symptôme** : CHV `claude.ai: dead`, export ai-chat en échec ; profil
     Hydra PC sans `sessionKey`, claude-ai-manager local avec org UUID invalide

     propagation automatisée (merge VPS + sync ai-export)

     sans passkey) ; unification #47 réduira les chaînes à resemer
2. **ai-export ne lit PAS les cookies du CHV**
   - **Symptôme** : CHV claude.ai alive + `cookies_claude.json` frais, mais
     export claude toujours en échec (« No Claude organizations found »)
   - **Cause** : troisième chaîne indépendante (Hydra PC → `sync_cookies_to_dropbox.py`
     → mount → `secrets.enc`) — les fichiers CHV n'ont aucun consommateur
   - **Solution** : régénérer + pousser `cookies.json` (rclone manuel, app
     Dropbox désactivée) ; unification tracée (#47)
   - **Prevention** : la carte des 3 chaînes est documentée ici et dans #47
