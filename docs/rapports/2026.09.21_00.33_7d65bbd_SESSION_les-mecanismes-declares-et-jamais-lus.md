## Decisions

1. **Gamme refusée sur la chair uniquement** — **Choix** : `blacklist_brand` `PRIX BAS` et
   `POUCE` avec portée `animal_protein`. — **Rationale** : la plainte porte sur la chair, pas
   sur les conserves ou le papier toilette. — **Alternative rejetée** : bannir l'id seul (un id
   voisin contourne en une semaine), ou bannir la gamme partout (interdit le premier prix utile).
2. **Une préférence déclare ce qu'elle ne sait pas mesurer** — ADR 0023.
3. **La charge se lit dans les étapes, pas sur l'horloge** — ADR 0024.
4. **Un interdit se lit à une tablée ; les résidents par défaut** — ADR 0025.
5. **Une part déclarée prime sur le moteur** — le cuisinier a toujours le dernier mot ;
   le moteur ne comble que les trous, sinon la liste de courses achète les deux.

## Problems

1. **La règle n'existait dans aucun système** — **Symptôme** : poulet `PRIX BAS` racheté malgré
   une consigne explicite. — **Cause** : la consigne vivait dans une conversation claude.ai de
   nutrition ; `shopping_preference` était écrite et jamais lue. — **Solution** : gate de
   validation en code. — **Prévention** : une préférence énoncée s'écrit en base **dans la
   minute**, la conversation n'est pas un système.

2. **Deux vérités dans le même endpoint** — **Symptôme** : `/menus/.../compatibility` annonçait
   1 conflit là où il y en avait 3. — **Cause** : les conflits se calculaient sur le JSONB
   `menu.meals` (que `PATCH /meals/{id}` ne met jamais à jour) et sur le **titre** du plat,
   pendant que les réparations lisaient les ingrédients de `menu_meal`. — **Solution** : une
   seule source, `menu_meal`, et un contrôle sur les ingrédients. — **Prévention** : deux
   chemins de lecture dans une même réponse est un bug, même quand les deux « marchent ».

3. **Un détecteur qui se trompe se mesure** — **Symptôme** : `overnight-oats` (5 min, on mélange
   et on dort) classé plat de week-end, `ninja-creami` (10 min) classé exigeant. — **Cause** :
   j'avais compté le repos comme du façonnage et le nombre d'étapes comme de l'attention.
   — **Solution** : les deux critères retirés après mesure sur 104 recettes. — **Prévention** :
   un détecteur se confronte au corpus **avant** d'être publié, jamais après.

4. **Un plat interdit posé au menu par l'agent** — **Symptôme** : `gratin-de-poissons-aux-legumes`
   (riz blanc, interdit pour Julien) placé lundi soir. — **Cause** : les 37 recettes moissonnées
   n'ont été confrontées à aucune contrainte à l'import. — **Solution** : corrigé en riz complet,
   et le contrôle du menu lit désormais les ingrédients. — **Prévention** : une recette importée
   passe au contrôle de compatibilité **avant** d'entrer au menu.

5. **Une écriture API effaçait la date de création** — **Symptôme** : `created IS NULL` sur les
   38 fiches. — **Cause** : `created=$27` s'appliquait aussi au `ON CONFLICT DO UPDATE`, donc
   toute réécriture d'une fiche existante nullait sa date. — **Solution** :
   `COALESCE(recipe.created, $27, CURRENT_DATE)`, 40 lignes rattrapées. — **Prévention** : dans
   un upsert, la branche UPDATE ne doit jamais écrire un champ « date de naissance ».
