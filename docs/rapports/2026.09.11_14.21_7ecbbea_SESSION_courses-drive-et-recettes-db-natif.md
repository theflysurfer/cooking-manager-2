## Decisions
1. **Courses = l'ordre fait foi, pas le panier** — reporter la pantry depuis
   `grocery_order_detail`, pas depuis notre panier proposé. Rationale : Julien a modifié au
   checkout ; l'ordre est la vérité de ce qui est entré chez lui.
2. **Voie (b) choisie** (DB seule source pour les recettes) — mais **Phase 2 en pause**
   (décision explicite « Phase 1 suffit pour l'instant »). Le vault reste source en attendant.
   Consigné en **ADR 0020**.
3. **Format d'auteur = markdown body** — le write API accepte « un .md en JSON » et re-parse
   ingrédients/étapes via `parse_recipe_body`, comme l'ingest. Julien ne perd pas le modèle
   d'écriture, seulement l'emplacement Obsidian (à terme).

## Problems
1. **Panier « vide » qui a inquiété Julien** — Symptôme : son Chrome montrait 0,00 €.
   Cause : j'étais en phase recherche (skill : tout chercher avant le 1er ajout, sinon le
   self-heal détache le panier), rien d'ajouté encore. Résolu par la boucle de feedback
   chrome-relay. Prévention : annoncer explicitement « recherche d'abord, ajouts ensuite ».
2. **Périmètre (b) plus large que prévu** — Découverte : l'import photo/URL passe par
   recipe-manager (8796), dont le `commit` écrit un `.md` dans le vault. Retirer l'ingest CM2
   sans changer recipe-manager casserait l'import. → Phase 2 est cross-repo. Consigné ADR 0020.
3. **Aucun venv de dev local** (python masqué par le stub Windows Store) — gates impossibles en
   local. Contourné en ajoutant ruff+pytest au venv du VPS et en tournant les gates côté
   serveur, sans toucher la prod (le service tourne depuis site-packages, `git pull` seul ne
   change rien tant que `pip install` n'est pas relancé). Lieu à confirmer.
4. **Gate commentaires rouge (exit 1) — pré-existant, pas une régression** : `gen_staple_fiches.py`
   (12 constats, non touché) + docstrings de style maison. Zéro commentaire `#` ajouté cette
