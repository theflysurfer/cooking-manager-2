## Decisions

1. **Le séjour l'emporte sur l'absence** (pas l'inverse)
   - **Rationale** : le bug Bègles est précisément « absent du foyer » lu comme
     « pas de repas ». Un séjour avec `cooking=TRUE` signifie qu'on cuisine sur
     place → ses membres sont à table, l'absence du foyer principal n'a plus de
     sens sur cette période
2. **Amorçage passkey délégué à un geste humain unique**
   - **Choix** : ne PAS tenter de contourner la vérification Google (pas de
     mot de passe manipulé, pas de commandeering de la session Hydra live)
   - **Rationale** : c'est le point irréductible du design passkey ; tout le
     reste est automatisé autour
3. **Fallback constantes conservé dans `presence.py`**
   - **Rationale** : `attendees()` sans `HouseholdConfig` garde le comportement
     historique — 100 % rétrocompatible, les 114 tests d'origine passent

## Problems

1. **Enrôlement passkey headless impossible** — testé 4 façons (headless-shell
   → `signin/rejected` ; ephemeral context + storage_state → rejected ;
   profil copié → `signin/identifier` logged out ; vraie session Hydra →
   `confirmidentifier` puis `challenge/pk`). Conclusion : geste humain unique
   requis. Documenté dans #1
2. **Faux positif carbonara** — « Tagliatelles carbonara **végétarienne** »
   déclenche une alerte pescetarian (`carbonara` ∈ liste MEAT). Pré-existant,
   pas introduit ici. Tracé dans #61
