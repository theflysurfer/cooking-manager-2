## Decisions

1. **food_form table** — Choix : table dédiée `(food_key, label, kcal, protein, carbs, fat)`,
   pas un JSONB multi-formes ni des clés dupliquées. Rationale : séparation propre, querying
   individuel des macros. Alternative rejetée : JSONB imbriqué (pas queryable).
2. **Migration totale** — Choix : tout dans food_form, vider `food.macros_per_100g`. Pas de
   double lecture. Rationale : source unique.
3. **18 multi-formes** — Choix : importer TOUTES les formes (cru/cuit, 5/10/15/20%). Pas de
   forme par défaut. Rationale : `FoodEntry.macros_for()` dispatch déjà par mot-clé.
4. **Pas de cache** — Choix : YAGNI, 163 rows <1ms. Alternative : TTL dict.
5. **parse_food_sheet** — Choix : supprimer (plus aucun appelant production). Alternative :
   garder pour OCR/étiquettes futures — trop spéculatif.

## Problems

1. **Dropbox propagation delay** — Symptôme : fichier supprimé localement, encore visible sur le
   mount rclone VPS. Cause : l'app Dropbox desktop sync vers le cloud n'est pas instantanée.
   Solution : `rclone delete` directement sur le remote Dropbox depuis le VPS, plus fiable que
   d'attendre la propagation. Prévention : pour les mutations critiques sur le vault monté,
   toujours passer par `rclone` côté VPS.
