## Decisions
1. **`Requires=` au lieu de `Wants=` pour recipe-manager**
   - **Choix** : CM2 refuse de démarrer si recipe-manager est absent
   - **Rationale** : CM2 a des FK vers les tables recettes ; sans elles, `CREATE TABLE menu_meal` échoue — mieux vaut un échec explicite qu'un crash silencieux au runtime
   - **Alternative rejetée** : `Wants=` (le service démarre quand même et échoue plus tard, diagnostic plus difficile)

2. **`DATABASE_URL` en `Environment=` plutôt qu'en credstore**
   - **Choix** : DSN en clair dans le fichier unit (comme CM2)
   - **Rationale** : le credential `recipe-manager-db-url` n'existait pas sur le VPS, et le DSN utilise le même user/pass que CM2 (déjà en clair). Uniformité
   - **Alternative rejetée** : créer un nouveau credential credstore (overhead pour un DSN local qui n'est pas un secret sensible — même VPS, même réseau)

3. **Absorption complète plutôt que dépendance pip**
   - **Choix** : copier les 8 modules de recipe-parser dans `url_parser/` au lieu d'ajouter recipe-parser comme dépendance
   - **Rationale** : recipe-parser n'avait qu'un seul consommateur (Waaker), le code est petit (~500 lignes), et un sous-package est plus simple qu'un package pip séparé à maintenir

## Problems
1. **`LoadCredentialEncrypted` pour un credential inexistant**
   - **Symptôme** : recipe-manager refuse de démarrer, `ExecMainStatus=243`, journal vide
   - **Cause** : `LoadCredentialEncrypted=recipe-manager-db-url:...` dans l'unit, mais le credential n'avait jamais été créé sur le VPS
   - **Solution** : retirer la ligne, utiliser `Environment=DATABASE_URL=...` directement
   - **Prévention** : ne jamais déclarer un `LoadCredentialEncrypted` sans avoir d'abord créé le credential via `systemd-creds encrypt`

2. **`setuptools.backends._legacy:_Backend` introuvable**
   - **Symptôme** : `pip install .` échoue à l'import du build backend
   - **Cause** : `pyproject.toml` utilisait un backend interne non exposé publiquement
   - **Solution** : remplacé par `setuptools.build_meta` (standard)

3. **`deploy/` détecté comme second package**
   - **Symptôme** : `pip install .` installe un package `deploy` fantôme
   - **Cause** : flat-layout de setuptools détecte tout dossier avec des fichiers Python
   - **Solution** : `[tool.setuptools.packages.find] include = ["recipe_manager*"]`

4. **`Requires=postgresql-shared.service` — unit introuvable**
   - **Symptôme** : recipe-manager ne démarre pas, dépendance manquante
   - **Cause** : PostgreSQL tourne dans un conteneur Docker, pas en service natif systemd
   - **Solution** : remplacé par `Requires=docker.service`

5. **Waaker appelle `/parse-html`, pas `/parse`**
   - **Symptôme** : le port est mis à jour mais Waaker n'utilise pas le bon endpoint
   - **Cause** : Waaker envoie du HTML pré-fetchté (stealth-fetch), pas une URL à fetcher
   - **Solution** : ajouté `POST /parse-html` qui accepte `{html, url, enable_llm}` et appelle `parse_recipe_html()` directement
