## Decisions

1. **Ne pas pousser les commits d'une autre session**
   - **Choix** : le MarketPlace porte 2 commits locaux non poussés (travail leboncoin,
     23:55) — laissés tels quels, signalés.
   - **Rationale** : ils ont l'air finis, mais « avoir l'air fini » n'est pas « être prêt à
     publier ». C'est la même classe d'erreur que le `git add -A` de la veille.
   - **Alternative rejetée** : pousser pour laisser le dépôt « propre » — la propreté ne
     justifie pas de publier le travail de quelqu'un d'autre.

2. **Corriger la description à la source, pas dans le registre**
   - **Choix** : réécrire `description` dans le `package.json` de CM2.
   - **Rationale** : `discover.py` lit le `package.json` en priorité ; corriger
     `projects.json` aurait été écrasé à la régénération suivante.
   - **Alternative rejetée** : un override manuel de description — un fichier de plus à
     tenir, pour un défaut qui se corrige à sa racine.

## Problems

1. **`discover.py` seul détruit la stack de dizaines de projets, en silence**
   - **Symptôme** : une mise à jour ciblée d'un projet produit **793 lignes modifiées** dans
     `projects.json`, avec un **solde négatif de 233**.
   - **Cause** : `discover.py` régénère l'artefact **à plat** et écrase les champs posés par
     `enrich-from-claude-md.py` — `backend`, `database`, `frontend`, `hosting`, `ui`
     disparaissaient sur ~66 projets. Les deux skills énonçaient l'ordre **à l'envers**.
   - **Solution** : relancer `enrich` après `discover` → le diff retombe à 48 lignes.
     Doctrine corrigée dans les deux skills (`494d26b`).
   - **Prévention** : le vrai piège n'est pas l'ordre, c'est que **le script a l'air d'avoir
     réussi** — `rc=0`, résumé des langages affiché. Rien ne distingue un succès d'une perte
     de masse sauf la lecture du diff. D'où le garde-fou écrit noir sur blanc : *un diffstat
     de plusieurs centaines de lignes sur une mise à jour CIBLÉE est un signal d'alarme*.

2. **Le registre décrivait CM2 comme un outil de compatibilité iOS**
   - **Symptôme** : `description = "Outillage de DEV uniquement (compat iOS 12)…"`.
   - **Cause** : `discover.py` lit `package.json` **avant** CLAUDE.md/README, et celui de CM2
     est dev-only — il se décrivait donc lui-même.
   - **Solution** : description réécrite pour nommer le projet **tout en conservant**
     l'avertissement, qui reste utile en place (il empêche d'ajouter un build).
   - **Prévention** : noté dans la skill registry — un `package.json` d'outillage fait
     décrire l'outillage au registre.

3. **Un `sorted()` de confort a produit 125 lignes de diff pour 3 entrées**
   - **Symptôme** : première tentative sur `repo_skills.json` → 125 insertions / 105 suppressions.
   - **Cause** : round-trip JSON avec réordonnancement — un reformatage déguisé en ajout.
   - **Solution** : `git checkout --` puis insertion chirurgicale → 20 insertions, 0 suppression.
   - **Prévention** : sur un fichier tenu à la main, éditer le **texte**, pas la structure.
     Un diff qui dépasse le changement qu'on décrit rend la relecture impossible.
