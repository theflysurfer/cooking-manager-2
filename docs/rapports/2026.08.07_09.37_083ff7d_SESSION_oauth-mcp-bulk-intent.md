## Decisions
1. **MCP sur le VPS, pas dans le proxy gateway local**
   - **Choix** : déployer comme service VPS autonome (port 3868, systemd, nginx)
   - **Rationale** : correction de Julien — tous les MCP sont sur le VPS, exposés par Google OAuth. Le proxy gateway local ne sert que pour les MCP stdio locaux.
   - **Alternative rejetée** : enregistrement dans `overrides.yaml` du proxy gateway (port 8750), qui n'offre pas d'authentification Google.

2. **Import `fastmcp` (pas `mcp.server.fastmcp`)**
   - **Choix** : `from fastmcp import FastMCP` au lieu de `from mcp.server.fastmcp import FastMCP`
   - **Rationale** : le package `mcp` (v2.0.0) expose un `FastMCP.run()` minimaliste sans `host`/`port`/`allowed_hosts`. Le package `fastmcp` (v3.4.6) expose la vraie API avec tous les paramètres nécessaires au déploiement HTTP authentifié.

3. **Nom de service secrets : `cooking` (pas `mcp-vps-cooking`)**
   - **Choix** : service name court dans `build_google_auth("cooking")` et `_secrets_path("cooking")` → `/home/automation/cooking/secrets.enc`.
   - **Rationale** : le code vit dans `/opt/cooking-manager-2/` (pas sous `/home/automation/mcp-vps-*/`), et le credential name dérivé est `mcp-key-cooking`.

## Problems
1. **421 "Misdirected Request" derrière nginx**
   - **Symptôme** : toutes les requêtes via le reverse proxy retournent 421.
   - **Cause** : FastMCP/Starlette rejette les requêtes dont le `Host` header ne correspond pas au bind address (`127.0.0.1`). Le snippet partagé `mcp-proxy.conf` passe `Host $host` (le domaine externe).
   - **Solution** : passer `allowed_hosts=["cooking-mcp.srv759970.hstgr.cloud"]` à `mcp.run()` pour whitelister le hostname externe.
   - **Prévention** : tout nouveau MCP derrière nginx doit déclarer `allowed_hosts`.

2. **`FastMCP.run()` n'accepte pas `host`/`port` (package `mcp`)**
   - **Symptôme** : `TypeError: FastMCP.run() got an unexpected keyword argument 'host'`
   - **Cause** : le code importait depuis `mcp.server.fastmcp` (le package `mcp` v2.0.0) dont `run()` n'accepte que `transport` et `mount_path`. Le package `fastmcp` (v3.4.6) a la bonne API.
   - **Solution** : changer l'import vers `from fastmcp import FastMCP`.

3. **Permissions `/home/automation/cooking/.local/`**
   - **Symptôme** : `PermissionError: [Errno 13] Permission denied: '/home/automation/cooking/.local'`
   - **Cause** : le répertoire `/home/automation/cooking/` créé par root n'appartenait pas à `mcp-run`. Le `GoogleProvider` crée un stockage OAuth dans `$HOME/.local/share/fastmcp/`.
   - **Solution** : `sudo chown -R mcp-run:mcp-run /home/automation/cooking`
