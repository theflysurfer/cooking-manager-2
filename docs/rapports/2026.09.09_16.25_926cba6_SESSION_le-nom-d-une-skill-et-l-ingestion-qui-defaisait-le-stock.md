### 1. #91 — l'ingestion ne touche plus au garde-manger

`_ingest_pantry` écrivait `pantry_item` par `ON CONFLICT (name_normalized, section) DO UPDATE`
**sans condition sur la source trouvée**. La table portant un `UNIQUE (name_normalized,
section)`, le vault ne créait pas un doublon à côté d'une ligne de drive : il la
**convertissait**, statut et `entered_at` compris.

Trois voies étaient ouvertes dans l'issue ; la voie 1 a été retenue — la lecture est retirée.
`Garde-manger.md` n'était plus écrit depuis le 2026-09-01 (ADR 0010), et une clause `WHERE
source = 'vault'` aurait laissé vivante la lecture d'un fichier décommissionné.

**Trouvaille au passage** : `commit_import_draft` (`app.py:2623`) appelle aussi `/api/ingest` —
**importer une fiche de livre défaisait le garde-manger**. L'issue ne le savait pas.

Vérifié par le comportement, pas par `is-active` : `updated_at` **identique à la milliseconde**
sur les trois sources après une ingestion complète.

## Problèmes rencontrés

### Le job « publish artifact » ne publiait aucun artifact

**Symptôme** : aucun. **Cause** : `python src/trends.py --publish` fait un **déploiement VPS**
vers `ai-usage.<box>.hstgr.cloud`. Le schedule s'appelait `ai-usage-publish-artifact` et
écrivait « artifact republié » dans ses logs. **Le nom ET le log promettaient ce que le code ne
faisait pas** — j'ai annoncé un remplacement qui n'en était pas un avant de le vérifier.

**Prévention** : vérifier ce qu'une commande publie **vraiment** avant de la ranger dans une
famille. Corrigé dans `ad604fa`.

### Une skill chapeau qui recopiait ce qui existait déjà

**Symptôme** : la première version de `julien-sync-daily` portait des tables de commandes.
**Cause** : je n'avais pas audité le parc avant d'écrire. `julien-media-transcriber` couvrait
déjà tout le volet médias, `julien-cos-session` portait le moteur du briefing.

**Prévention** : auditer les skills existantes **avant** d'écrire une skill chapeau. Le patron
maison existait déjà (`julien-youtube-pipeline-run`, écrit trois jours plus tôt pour le même
cas).

### Un préfixe qui classe sans déclencher

**Symptôme** : `ops-slides` et `ops-hostinger` dans la même famille. **Cause** : j'avais typé
par ce que la skill *est*, pas par ce qu'on *dit* en la cherchant.

**Prévention** : un type ne prend un préfixe que si c'est le mot employé en cherchant. Décision
prise puis renversée dans la même session, sur objection d'usage.

### Le renommage partiel — deux fois

**Symptôme** : aucun. **Cause** : le script de renommage ne scanne ni `scripts/*.ps1`, ni
`.claude/commands/`, ni la racine du marketplace, ni les `CLAUDE.md` des projets.

Trouvés par la vérification finale : une **slash-command invoquant une skill disparue**, une
**permission `Skill(...)` morte** dans `settings.local.json`, des fixtures de test périmées, et
**23 `CLAUDE.md` de projets**.

**Prévention** : après tout renommage, balayer au-delà du périmètre du script.

### Deux skills vivaient hors de git

**Symptôme** : deux entrées de `~/.claude/skills/` n'étaient pas des jonctions.
**Cause** : créées directement là, hors procédure. `julien-ref-cookie-health-box` faisait 12 Ko
et n'avait **aucune sauvegarde**. Migrées dans le MarketPlace.

## Décisions

1. **L'ingestion cesse de lire, plutôt que de respecter une règle.** Un garde-fou structurel ne
   se perd pas dans un refactor ; une clause conditionnelle si (ADR 0017).
2. **Le type d'une skill gouverne son nom, mais seulement s'il se prononce.** Un nom sert
   d'abord à être trouvé (ADR 0014, MarketPlace).
3. **Une skill chapeau route, elle ne réimplémente pas.** Deux versions d'une procédure
   divergent en silence.
