### Le vrai bug de session Auchan, trouvé et réparé (pas contourné)
- Symptôme : `grocery_orders` rendait 0 commande, session VPS `ANONYME` malgré plusieurs
  reseeds de cookies fraîchement authentifiés (dont un login HydraSpecter complet jusqu'au
  challenge passkey, validé par Julien).
- Cause réelle : `SecretStore.set()` (`shared/mcp_secrets.py`) échoue **silencieusement** hors
  du mount namespace systemd — la clé Fernet ne vient que de `LoadCredentialEncrypted=`,
  invisible en SSH manuel. Le script de reseed loggait « persisted » même quand rien n'était
  écrit sur disque (juste un `logger.warning`, jamais levé).
- Réparé en relançant le reseed sous `systemd-run` avec le même `LoadCredentialEncrypted=` et
  le même user/group (`mcp-run`, pas `automation` — `secrets.enc` n'est écrivable que par son
  propriétaire réel) que le service `mcp-vps-auchan`, puis `grocery_reload_cookies` sur le
  service déjà démarré. Vérifié : `/client/mes-commandes` 200 CONNECTE, 6 commandes réelles
  rendues.
- Documenté dans la skill `cooking-manager-auchan-drive` (§ Session Auchan) avec la commande
  exacte, pour que la prochaine session n'ait pas à redécouvrir ça.

## Problems
1. **`SecretStore.set()` échoue en silence hors systemd** — **Symptôme** : reseed de cookies
   Auchan répété sans effet, script annonçant « persisted » à chaque fois — **Cause** : clé
   Fernet accessible uniquement via `LoadCredentialEncrypted=` (mount systemd), absente en SSH
   manuel ; l'échec est un `logger.warning`, jamais une exception — **Solution** : `systemd-run`
   avec le credential + user/group du service réel — **Prévention** : documenté dans le skill ;
   piste ouverte côté mcp-vps pour lever une exception au lieu de logger (non traité cette
   session, pas d'issue ouverte dessus — periph au sujet du jour).
2. **`grocery_order_detail` rend des noms de produit corrompus** — **Symptôme** : `"})();"` sur
   les 26 lignes d'une commande — **Cause probable** : scraper capturant un fragment de
   `<script>` au lieu du sélecteur produit, page `mes-commandes` possiblement changée —
   **Solution de contournement** : `grocery_download_invoice` (PDF lisible, mais pas d'EAN) —
   **Prévention** : `mcp-vps#181` ouverte, pas corrigée cette session.
3. **Skill `cooking-manager-auchan-drive` ne mentionnait pas HydraSpecter/Chrome Relay comme
   voie de réparation rapide** — **Symptôme** : signalé par Julien — **Cause** : la skill
   supposait une « session PC vivante » sans dire comment l'obtenir — **Solution** : section
   ajoutée renvoyant vers `julien-hydra-login` (défaut) et Chrome Relay (alternative) —
   **Prévention** : écrit, donc consultable la prochaine fois.
