# Analyse : merge des outils Auchan Drive

> Trois couches logicielles distinctes coexistent pour interagir avec Auchan Drive.
> Cette analyse documente ce qui marche, ce qui ne marche pas, et ce qu'il faut
> consolider.

## 1. Les trois couches

### 1a. MCP local `backend/auchan_mcp.py` (Cooking Manager 2)

**Repo** : `theflysurfer/cooking-manager-2`
**Transport** : stdio (`python -m backend.auchan_mcp`)
**Client** : `backend/auchan.py` — reverse-engineering SSR + API Gravitee, httpx

**11 tools** : search, product_detail, cart get/add/remove/update, persist_cart,
search_and_add, bulk_add, set_store, set_token.

**Forces** :
- Seul outil capable de supprimer un article et modifier les quantités
- Recherche SSR avec `selectolax` (résolution fiable des `offer_id`)
- Enrichissement nutritionnel via EAN → Open Food Facts
- Persistance des choix en JSON (traçabilité des courses)
- Fonctionne pour n'importe quel magasin (via `set_store`)

**Faiblesses** :
- Nécessite un token Bearer JWT extrait manuellement (expire en quelques minutes)
- Transport stdio = pas branché par défaut dans les sessions Claude Code
- Recherche SSR liée à l'IP (cookies `lark-*` invalidés si routés via proxy)
- Pas déployé en remote (pas de connecteur claude.ai)

**Bilan sessions** :
- 3 août : **22 articles, ~86 €** (Aubagne, 4 couverts) — SUCCÈS
- 4 août : **nettoyage 59 → 34 articles** (25 retraits) — SUCCÈS

### 1b. Wrapper MCP VPS `mcp-vps-auchan` (port 3854)

**Repo** : `theflysurfer/mcp-vps` (monorepo)
**Transport** : Streamable HTTP, exposé via nginx + SSL sur claude.ai
**Client** : `curl_cffi` (obligatoire : httpx reçoit un body vide depuis api.auchan.fr)

**Tools** : search, add_to_cart, remove_from_cart (ajouté 09/08), get_cart,
search_and_add, product_detail, favorites, orders, order_detail, download_invoice,
reload_cookies, set_cart_id.

**Forces** :
- Accessible depuis claude.ai et Claude Code sans configuration locale
- `curl_cffi` contourne le TLS fingerprinting d'Auchan
- OAuth Google intégré (auth partagée avec tous les MCP VPS)
- Cookies gérés via SecretStore chiffré (pas de plaintext sur le VPS)

**Faiblesses** :
- Cookies VPS expirés = panier invisible (pas de self-heal automatique)
- `search_and_add` inutilisable (pertinence catastrophique du 1er résultat)
- `remove_from_cart` renvoie 500 sur certains articles (bug côté Auchan)
- Pas d'enrichissement nutritionnel
- Pas de persistance JSON des choix
- Bug `upload_cookies()` : `reload_cookies()` écrase les cookies uploadés

**Bilan sessions** :
- 9 août matin : **~60 articles, ~207 €** (Bègles, 10 couverts) — SUCCÈS PARTIEL
  (4 articles non ajoutés, 2 erronés, ajustements en attente)

### 1c. Connecteur claude.ai pré-existant

**Origine** : connecteur déclaré sur claude.ai, connecté au VPS port 3854

**Tools** : mêmes que le wrapper VPS (même serveur sous-jacent)

**Problème fondamental** : dans certaines sessions, `grocery_search` ne résout pas
les `offer_id` (retourne `""`) → `grocery_add_to_cart` échoue en 500.

**Bilan sessions** :
- 9 août nuit : **1 seul article** ajouté sur ~55 tentés — ÉCHEC
  (utilisé par erreur à la place du MCP local)

## 3. Problèmes récurrents

### 3a. Fragmentation des outils (problème #1)

Trois implémentations indépendantes du même client Auchan :
- `backend/auchan.py` (CM2) : le plus complet, httpx
- `mcp_vps_auchan/auchan_client/client.py` (MCP VPS) : curl_cffi, pas d'enrichissement
- Le connecteur claude.ai pointe vers le MCP VPS

**Conséquence** : les fixes d'un côté ne profitent pas à l'autre. Le bug
`upload_cookies()` existe dans le MCP VPS mais pas dans CM2. Le `remove_from_cart`
a été ajouté au MCP VPS le 09/08, il existait déjà dans CM2 depuis le 03/08.

### 3b. Authentification fragile (problème #2)

- **Token JWT** : expire en quelques minutes, extraction manuelle depuis HydraSpecter
- **Cookies VPS** : SecretStore chiffré, mais expiration sans self-heal
- **Cookie Health Manager** (issue #9) : renouvellement automatique pas encore implémenté
- **Session SSR** : liée à l'IP, invalidée si routée via proxy résidentiel

### 3c. `search_and_add` inutilisable (problème #3)

Le 1er résultat de recherche Auchan est souvent hors sujet :
- « carotte france 1kg » → petits pois carottes D'Aucy
- « feta 200g » → tranche de fromage au lait de vache

**Seule méthode fiable** : two-step (search → vérification humaine → add).

### 3d. Quantités et doublons (problème #4)

- Appels parallèles à `add_to_cart` : quantités ignorées silencieusement
- Saumon fumé : 7 paquets au lieu de 3 (ajouts multi-passes sans cumul)
- Pas de vérification anti-doublon systématique

## 4. Recommandation : consolider vers un seul client

### Option A — MCP local CM2 comme source unique (RECOMMANDÉ)

Le MCP local `backend/auchan_mcp.py` est le plus complet :
- 11 tools (vs 12 pour le VPS, mais sans enrichissement ni persistance)
- Suppression et update qui marchent depuis le 3 août
- Enrichissement nutritionnel (EAN → OFF)
- Persistance JSON des choix

**Plan** :
1. Porter `curl_cffi` dans `backend/auchan.py` (résout le TLS fingerprinting)
2. Déployer le MCP CM2 sur le VPS (port dédié, Streamable HTTP)
3. Connecter via claude.ai (remplace le connecteur actuel)
4. Déprécier `mcp-vps-auchan` du monorepo MCP VPS
5. Implémenter le renouvellement automatique des cookies (cookie-health-manager#9)

### Option B — Merger les features du MCP local dans le VPS

Moins de disruption mais double maintenance permanente.

**Plan** :
1. Porter l'enrichissement nutritionnel dans `mcp-vps-auchan`
2. Porter la persistance JSON des choix
3. Corriger le bug `upload_cookies()`
4. Garder les deux clients synchronisés (dette)

### Priorité immédiate (indépendante de A/B)

- Corriger le bug `upload_cookies()` dans `mcp-vps-auchan`
- Implémenter la vérification anti-doublon (check panier avant ajout)
- Forcer les appels `add_to_cart` en séquentiel (pas de parallélisation)
- Cookie Health Manager #9 : renouvellement automatique session Auchan

## 5. Historique des courses réussies avec Claude

### Semaine Aubagne (3-4 août) — LE MODÈLE QUI MARCHE

**Workflow** :
1. Session claude.ai avec MCP local `backend/auchan_mcp.py` branché en stdio
2. `set_token` avec Bearer JWT frais (extrait de HydraSpecter)
3. `set_store` pour Aubagne
4. Recherche two-step : `search("saumon fumé")` → Claude propose les résultats →
   Julien valide → `add_to_cart`
5. Nettoyage le lendemain : `get_cart` → identification des excédents →
   `remove_from_cart` sur chaque
6. JSON de traçabilité sauvegardé (`data/shopping_choices_2026-08-03.json`)

**Résultat** : 34 articles, 142,89 €, 4 couverts, sans erreur.

**Pourquoi ça a marché** :
- MCP local = toutes les opérations (add, remove, update) disponibles
- Two-step = pas d'ajout aveugle
- Nettoyage post-achat = filet de sécurité
- Token frais extrait au début de session

### Semaine Bègles (8-9 août) — PARTIELLEMENT RÉUSSI

**Workflow** :
1. Planification : 11 recettes, menu, artefact liste de courses (session CM2 du 08/08)
2. Tentative avec connecteur claude.ai → échec (offer_id vides)
3. Bascule vers MCP VPS → ~60 articles ajoutés
4. Reste : 4 à ajouter, 2 à retirer, quantités à ajuster

**Pourquoi c'était moins fluide** :
- Mauvais outil choisi d'abord (connecteur claude.ai au lieu du MCP local)
- MCP local pas branché (stdio, pas déclaré dans la session)
- Cookies VPS expirés entre les sessions
- `search_and_add` utilisé au début → articles erronés
