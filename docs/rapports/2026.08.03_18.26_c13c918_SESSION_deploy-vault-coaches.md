## Decisions

1. **PostgreSQL plutôt que SQLite**
   - **Choix** : PostgreSQL via le conteneur `postgresql-shared` déjà sur le VPS
   - **Rationale** : migration globale SQLite→PG prévue pour toutes les mini-apps
   - **Alternative rejetée** : SQLite (pas de serveur partagé, pas de types array/jsonb natifs)

2. **Chemin d'installation `/opt/cooking-manager-2`**
   - **Choix** : dossier séparé de cooking-manager v1
   - **Rationale** : v1 (CLI Python) occupe déjà `/opt/cooking-manager`

3. **Seed depuis cuisine.json plutôt qu'ingest vault initial**
   - **Choix** : `backend/seed.py` pour le premier chargement
   - **Rationale** : le vault Cuisine n'existait pas au moment du premier déploiement (incident de suppression du 2026-07-08, restauré depuis)

## Problems

1. **VAULT_ROOT incorrect**
   - **Symptome** : `POST /api/ingest` ne trouvait pas les recettes
   - **Cause** : le chemin par défaut omettait `/Noyau/` dans le path
   - **Solution** : corrigé dans config.py, service systemd, et déployé
   - **Prevention** : le chemin est maintenant documenté dans le `_coach.md`

2. **ERR_SSL_UNRECOGNIZED_NAME_ALERT sur Android**
   - **Symptome** : le site ne charge pas sur Android (navigateur Chrome)
   - **Cause** : probablement un cache client Android, le certificat est valide côté serveur (vérifié via openssl s_client + certbot)
   - **Solution** : non résolu — fonctionne en desktop
