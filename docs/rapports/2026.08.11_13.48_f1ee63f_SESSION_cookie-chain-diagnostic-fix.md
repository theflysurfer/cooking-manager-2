# Session : Diagnostic et correction de la chaîne de cookies Auchan Drive

## Metadata
- **Date** : 2026-08-11 13:48
- **Duration** : ~1 h

- **Project** : 2026.08 Cooking Manager 2

## Objective

Comprendre pourquoi la session Auchan Drive expire systématiquement malgré
l'infrastructure en place (Cookie Health Manager, Cookie Health VPS, MCP VPS)
et corriger les maillons cassés.

## Achievements

- **Audit complet de la chaîne de cookies** — cartographie des 5 composants
  (Cookie Health Manager, Cookie Health VPS, MCP VPS Auchan, HydraSpecter,
  idle-queue schedule #89) et de leurs interactions
- **Bug #10 identifié et corrigé** (MCP VPS Auchan) — `upload_cookies()` ne
  mettait pas à jour `_cookies_source`, donc `reload_cookies()` rechargeait
  les cookies périmés du disque au lieu des frais du SecretStore. Le self-heal
  était un no-op
- **Warm URL VPS corrigée** (Cookie Health VPS) — `platforms.py` pointait sur
  `https://www.auchan.fr/` (homepage, toujours 200 sans session) au lieu de
  `https://www.auchan.fr/client/mes-commandes` (page authentifiée qui force
  le roulement du `connect.sid`)
- **Diagnostic de l'insuffisance VPS** — trois lacunes structurelles
  identifiées : warm URL erronée (corrigée), aucune ré-authentification
  automatique, seed initial = copie ponctuelle du PC

## Decisions

1. **Fix `_cookies_source = None` plutôt que pointer vers le SecretStore**
   - **Choix** : mettre `_cookies_source` à `None` quand `upload_cookies()`
     est appelé sans `save_path`, forçant le passage par le SecretStore
     (priorité 0 dans `load_auchan_cookies()`)
   - **Rationale** : le SecretStore est déjà la priorité 0 dans le code
     existant — il suffit d'empêcher le fallback fichier d'écraser les
     cookies frais. Changement minimal, une ligne
   - **Alternative rejetée** : écrire un fichier temporaire avec les cookies
     frais — ajouterait un état de plus à gérer

2. **Warm URL `/client/mes-commandes` alignée avec le Cookie Health Manager local**
   - **Choix** : même URL authentifiée sur les deux warmers
   - **Rationale** : le Cookie Health Manager local utilise déjà cette URL
     et elle force le roulement de `connect.sid`. Les `LOGIN_MARKERS` du VPS
     (`compte.auchan`, `keycloak`) détectent déjà la redirection en cas de
     session morte

## Problems

1. **Self-heal `reload_cookies()` = no-op**
   - **Symptôme** : HTTP 500 sur `grocery_add_to_cart` — 34/51 articles avec
     `NO_OFFER_ID` dans un batch le 9 août
   - **Cause** : `upload_cookies()` persistait les cookies frais dans le
     SecretStore mais laissait `_cookies_source` pointer vers un fichier
     périmé. `reload_cookies()` rechargeait les périmés par-dessus les frais
   - **Solution** : `_cookies_source = None` après `upload_cookies()` sans
     `save_path` — le fallback fichier ne peut plus écraser le SecretStore
   - **Prevention** : refs cookie-health-manager#10

2. **VPS warm sur la mauvaise URL**
   - **Symptôme** : Cookie Health VPS rapportait Auchan ALIVE alors que
     `connect.sid` était expiré depuis des heures
   - **Cause** : warm URL = `https://www.auchan.fr/` (homepage publique,
     toujours 200) au lieu de `/client/mes-commandes` (page authentifiée)
   - **Solution** : changé la warm URL dans `platforms.py`
   - **Prevention** : le VPS détectera désormais correctement les sessions
     mortes via les `LOGIN_MARKERS` existants

### Gotchas

- Le fix bug #10 ne suffit pas si le `SecretStore` n'a ni `set()` ni
  `reload()` (le `mcp-vps-shared` en manque — le `shared/mcp_secrets.py` les
  a). Si le serveur migre vers le package `mcp-vps-shared`, porter ces
  méthodes
- `connect.sid` est potentiellement lié à l'IP — si le VPS change d'IP, le
  cookie est invalide même frais
- Pas de playbook HydraSpecter pour re-login Auchan : quand la session est
  vraiment morte, l'intervention reste manuelle (alerte Telegram)
- Le double système de warm (local + VPS) écrit dans le même SecretStore
  sans coordination — risque de race condition
