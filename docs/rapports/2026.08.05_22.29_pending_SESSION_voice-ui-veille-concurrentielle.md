## Decisions
1. **Panneau persistant plutôt que toast éphémère**
   - **Choix** : `#mic-panel` avec zones séparées transcript/intent, fermable manuellement.
   - **Rationale** : en cuisine, un toast qui disparaît en 4 secondes ne laisse pas le temps de vérifier que le système a compris. La veille confirme que ce pattern (transcript+intent persistant) est inédit dans les apps cuisine.
   - **Alternative rejetée** : toast enrichi — même enrichi, un contenu éphémère ne permet pas la récupération d'erreur.

2. **L'espace vide est une niche, pas une disruption**
   - **Choix** : le verdict de la veille dit « étroitesse de la niche », pas « oubli du marché ».
   - **Rationale** : Jow (>3M utilisateurs FR) n'a pas ajouté de multi-convive en 5 ans. La demande existe (avis stores, Reddit) mais le ROI ne justifie pas la complexité pour les apps grand public.

## Problems
1. **Ollama model names (résolu en amont)**
   - **Symptôme** : 404 sur `qwen3:32b-cloud` et `qwen3-coder:cloud`.
   - **Cause** : le naming Ollama cloud est `qwen3.5:cloud`, pas déductible.
   - **Solution** : scrape de `ollama.com/search?c=cloud` pour découvrir les noms corrects.
   - **Prévention** : documenté dans `backend/config.py` — le modèle par défaut est `qwen3.5:cloud`.

2. **`showMicPanel` non accessible depuis `evaluate()` Playwright**
   - **Symptôme** : `ReferenceError: handleVoiceResult is not defined` dans le test navigateur.
   - **Cause** : les fonctions sont au scope global du script mais Playwright `evaluate` voit un scope isolé.
   - **Solution** : test via manipulation DOM directe au lieu d'appels de fonctions JS.
