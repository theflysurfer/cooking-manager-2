## Decisions

1. **La base du Coach Nutrition plutôt qu'un téléchargement CIQUAL brut**
   - **Choix** : lire `Coaches/Coach Nutrition/aliments-vérifiés/` et appliquer `_coach.md`.
   - **Rationale** : la méthodologie existait déjà — ~240 fiches avec source et statut de
     confiance, et des règles écrites. Reconstruire à côté aurait créé une seconde vérité.
   - **Alternative rejetée** : ingérer la table ANSES (joignable, 3,6 Mo) et bâtir un
     appariement neuf — plus de code, moins de jugement humain incorporé.

2. **Refuser de trancher plutôt que deviner une forme d'aliment**
   - **Choix** : plusieurs colonnes `/100g` → l'ingrédient doit nommer sa forme, sinon
     `unresolved`.
   - **Rationale** : entre lentilles crues (339 kcal) et cuites (116), un défaut se trompe
     d'un facteur 3 sans qu'aucun signal n'apparaisse.
   - **Alternative rejetée** : prendre la première colonne (le comportement d'origine).

3. **Reporter l'isolation d'image (#66), ouvrir l'issue quand même**
   - **Choix** : la page entière part au modèle vision ; l'illustration vient de
     `generate-image`.
   - **Rationale** : seul axe dont le coût est sans rapport avec le bénéfice, et une parade
     gratuite existe qui préserve en plus l'unité visuelle du parc.
   - **Alternative rejetée** : dewarping cylindrique — un projet à part entière.

4. **Sévérité calibrée sur « ce qui ment », pas sur « ce qui manque »**
   - **Choix** : dans l'audit, une fiche sans macros est `serious`, pas `blocking`.
   - **Rationale** : elle produit **zéro chiffre**, pas un chiffre faux — et `coverage` le
     signale déjà. Le bloquant reste réservé aux données trompeuses.
   - **Alternative rejetée** : tout bloquant — un audit qui crie au loup cesse d'être lu.

## Problems

1. **Le vault du VPS est monté en LECTURE SEULE — le commit d'import aurait échoué**
   - **Symptôme** : premier test de bout en bout vert.
   - **Cause** : il écrivait dans `/tmp`. `/mnt/dropbox-full` est `ro` — `Read-only file system`.
   - **Solution** : `publish()` choisit sa voie selon ce qui est *réellement* inscriptible :
     écriture directe en local, zone de transit + `rclone copyto` sur le VPS.
   - **Prévention** : un test dédié simule le vault non inscriptible. Un test qui n'écrit
     que dans un `tmp_path` accessible ne peut pas voir ce cas.

2. **Deux bugs silencieux dans la lecture des fiches aliments**
   - **Symptôme** : des macros plausibles, et 47 fiches absentes du calcul.
   - **Cause** : (a) la 1ʳᵉ colonne n'est pas toujours `/100g` (`lentilles.md` : « Crues »
     puis « Cuites ») ; (b) **trois** dispositions de tableau coexistent, dont une
     transposée et une dont la base est annoncée par le *titre de section*.
   - **Solution** : parseur conscient de l'en-tête, des trois dispositions, et refusant
     d'inférer une base non déclarée.
   - **Prévention** : consigné dans CLAUDE.md ; l'audit contrôle les trois formes.

3. **Deux défauts que les 168 tests ne pouvaient pas voir**
   - **Symptôme** : 500 sur `/macros`, puis 24 s de latence.
   - **Cause** : `qty_min` arrive en `Decimal` (NUMERIC via asyncpg), et la base aliments
     est relue sur le mount FUSE à chaque requête (~7 s).
   - **Solution** : coercition + memoïsation (`load_food_base_cached`).
   - **Prévention** : sur du code qui lit des fichiers hétérogènes écrits à la main,
     **l'appel réel est le contrôle qui tranche**, pas la suite de tests.

4. **J'ai poussé un commit sur un gate pyright rouge**
   - **Symptôme** : `9f6104d` poussé avec 7 erreurs pyright.
   - **Cause** : ma sonde (`pyright | tail -3`) affichait l'avertissement de version et
     masquait le compte d'erreurs ; le `&& grep errors` réussissait sur « 7 errors ».
   - **Solution** : corrigé en `57e850e` ; sonde désormais `grep -E "^[0-9]+ error"`.
   - **Prévention** : **ne jamais filtrer la sortie d'un gate par `tail`** — un gate se lit
     en entier ou sur son code de retour, jamais sur une fenêtre.

5. **`git add -A` a embarqué le travail d'une autre session**
   - **Symptôme** : le commit de la skill contenait 5 fichiers étrangers.
   - **Cause** : `git add -A` dans un checkout partagé.
   - **Solution** : commit séparé en deux (`277eff6` + `57105bd`), `--force-with-lease`
     après vérification que le remote n'avait pas bougé.
   - **Prévention** : `git add <chemins explicites>` hors du repo de session. C'est aussi
     pourquoi le **repo-registry n'a pas été régénéré** ce soir : il porte 1 300 lignes de
     modifications non committées (Alentourie / Ontology Manager) — `discover.py` les aurait
     entremêlées.

### Gotchas

- **Ne jamais filtrer la sortie d'un gate par `tail`** — `pyright | tail -3` cache le compte
  d'erreurs derrière l'avertissement de version. Lire le gate en entier, ou son code retour.
- **Le vault du VPS est `ro`** : toute écriture y passe par une zone de transit + `rclone`.
  Compter ~30 s de propagation avant qu'une ingestion voie le fichier.
- **`load_food_base_cached()` est obligatoire** côté API : la base vit sur un mount FUSE
  (~7 s pour 240 fiches).
- **Une fiche aliment peut avoir plusieurs formes** — si une recette n'obtient aucune macro
  pour un ingrédient présent en base, chercher `forme ambiguë` dans `unresolved`.
- **`git add <chemins explicites>`** hors du repo de session : le checkout est partagé.
