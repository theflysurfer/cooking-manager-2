## Objective
Diagnostiquer le "Failed to fetch" du pipeline STT, remplacer Ollama cloud par Groq pour l'inférence LLM (latence ~300 ms au lieu de 60 s+), et câbler l'intent `swap_recipe` de bout en bout.

## Achievements
- **Diagnostic STT "Failed to fetch"** : `httpx.ReadTimeout` non capté par le `except RuntimeError` du endpoint → 500 non maîtrisé côté serveur, "Failed to fetch" côté navigateur. Double correction : timeout Ollama porté à 120 s + `httpx.TimeoutException` capté et converti en `RuntimeError`.
- **Migration Ollama → Groq** : le résolveur d'intent passe de Ollama cloud (`qwen3.5:cloud`, 10-60 s, timeout fréquent) à Groq LPU (`qwen/qwen3.6-27b`, `reasoning_effort=none`, ~300 ms). Clé réutilisée depuis le credstore existant (`bibliotheque-groq-key`, embedded name `groq-key`). Ollama conservé en fallback si Groq absent.
- **`run-with-cred.sh` exécutable** : le fichier était en 644 dans git → systemd ne pouvait pas l'exécuter → service coincé en "activating". Corrigé à 755.
- **Câblage `swap_recipe`** : l'intent vocal "changer la recette pour des pancakes demain matin" résout maintenant jour+créneau → `meal_id`, ouvre le picker de substitution pré-filtré avec le nom de recette.

## Decisions
1. **Groq plutôt qu'Ollama cloud pour l'intent**
   - **Choix** : Groq API (`api.groq.com/openai/v1`) avec `qwen/qwen3.6-27b`.
   - **Rationale** : pour une classification JSON à 8 intents, Ollama cloud est disproportionné (cold start 60 s+, timeout fréquent). Groq répond en ~300 ms. Clé déjà provisionnée dans le credstore VPS.
   - **Alternative rejetée** : fast-path par mots-clés (zéro dépendance, mais limité aux cas triviaux et ne gère pas les formulations naturelles).

2. **Réutiliser `bibliotheque-groq-key` plutôt que créer un credential dédié**
   - **Choix** : `LoadCredentialEncrypted=groq-key:/etc/credstore.encrypted/bibliotheque-groq-key`.
   - **Rationale** : même clé API, pas de raison de la dupliquer. L'embedded name `groq-key` est compatible.

## Problems
1. **`httpx.ReadTimeout` non capté (résolu)**
   - **Symptôme** : "Failed to fetch" dans le panneau vocal.
   - **Cause** : `httpx.ReadTimeout` n'est pas un `RuntimeError` → le `except RuntimeError` du endpoint ne le captait pas → 500 non structuré → le navigateur recevait un timeout réseau.
   - **Solution** : `except httpx.TimeoutException` dans `transcribe()` et `interpret()`, converti en `RuntimeError` avec `from None`.
   - **Prévention** : documenté dans CLAUDE.md (Groq comme backend LLM par défaut).

2. **`run-with-cred.sh` non exécutable (résolu)**
   - **Symptôme** : service "activating" indéfiniment après deploy.
   - **Cause** : git avait le fichier en mode 100644. `ExecStart` pointait vers un script sans bit +x.
   - **Solution** : `git update-index --chmod=+x deploy/run-with-cred.sh`.

3. **VPS avec fichiers locaux bloquant git pull (résolu)**
   - **Symptôme** : `git pull` échoue ("local changes would be overwritten").
   - **Cause** : le déploiement précédent avait été fait par tar, pas par git — les fichiers étaient présents mais non trackés.
   - **Solution** : `git checkout -- . && git clean -fd` puis `git pull`.
